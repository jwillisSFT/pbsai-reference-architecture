# Contributing to PBSAI

The Practitioner’s Blueprint for Secure AI (PBSAI) is published for open
technical review, implementation evaluation, and interoperability discussion.

Technical feedback, architecture questions, implementation experience,
control-mapping observations, interoperability proposals, identified defects,
and suggested improvements are welcomed through GitHub Issues.

## Governance and Change Authority

PBSAI is an independently governed reference architecture maintained through
authorized project maintainers.

Public participation in PBSAI review does not confer governance, maintainer,
approval, or decision-making authority over the project.

Submission, discussion, or acknowledgement of an issue does not imply
acceptance of a proposed change.

Authoritative PBSAI architecture documents, domain specifications, control
catalogs, mappings, interoperability artifacts, and related project materials
may be changed only through the project-maintainer change process.

Where public feedback identifies a potential architectural, structural, or
control-system change, the maintainers determine whether and how that matter
is incorporated into a future PBSAI release.

Copyright and patent rights remain as stated in LICENSE.txt and NOTICE.md.

## Public Technical Review

GitHub Issues are the public mechanism for submitting:

- architecture defects;
- architecture ambiguities;
- domain or control gaps;
- control-mapping concerns;
- interoperability concerns;
- Context Envelope or Output Contract concerns;
- evidence or provenance concerns;
- security-architecture concerns;
- governance or execution-boundary concerns; and
- implementation experience.

Reviewers should identify the relevant PBSAI artifact, domain, section, control
identifier, or mapping where applicable and provide a proposed resolution when
possible.

## Repository Changes

External review and feedback are conducted through GitHub Issues.

Pull requests affecting PBSAI architecture or controlled repository content are
restricted to authorized collaborators and maintainers.

Authoritative changes are implemented through the project-maintainer change
process and become effective only when incorporated into an authoritative
repository revision or release.

## Security Vulnerabilities

Do not disclose exploitable vulnerabilities, sensitive implementation details,
credentials, or other security-sensitive information in a public GitHub Issue.

Use the repository's private vulnerability-reporting mechanism for security
vulnerabilities.

## Intellectual Independence

Participation in public PBSAI review does not transfer ownership, governance,
project assets, trademarks, repositories, architectural authority, copyright,
or patent rights to reviewers, participating organizations, standards bodies,
alliances, or other third parties.

Specific materials separately contributed by a PBSAI rights holder or
maintainer to another project or organization are governed by the terms
applicable to those specific contributions.
